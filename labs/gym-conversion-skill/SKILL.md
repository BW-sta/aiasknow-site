# 健身房体验课成交执行 Skill

## 名称
Gym Trial Conversion Execution Skill

## 目标
不是给健身房老板“提高体验课成交率”的建议，而是直接接管体验课未成交客户的执行队列，直到客户成交、暂缓或流失。

## 输入
每个体验客户只需要最小信息：
- 姓名/称呼
- 体验时间
- 意向：高 / 中 / 低
- 主要卡点：价格 / 时间 / 还在比较 / 没回复 / 没明显卡点
- 当前状态
- 已跟进次数

## Skill 必须交付
1. 自动给每个客户计算优先级
2. 自动决定今天先联系谁
3. 自动生成该客户本次跟进内容
4. 自动给出本次唯一目标
5. 记录联系、回复、预约、成交、暂缓、流失
6. 每次状态变化后自动重新排序
7. 自动决定下一次动作
8. 成交后记录成交金额
9. 实时计算：联系数、回复数、预约数、成交数、成交金额
10. 最终输出真实执行结果，而不是一份建议报告

## 状态机
未处理
→ 已联系
→ 已回复
→ 已预约
→ 已成交

分支：
- 已联系 → 暂缓
- 已联系 / 已回复 → 流失
- 暂缓 → 重新激活

## 优先级
高意向优先；刚体验完优先；明确问过价格但未成交优先；已回复优先；多次无回复逐步降级；成交/流失退出执行队列。

## 每次只给一个动作
前台禁止同时给老板五条销售建议。

示例：
客户：王女士
当前判断：高意向 + 价格卡点 + 昨天体验

今天唯一动作：
联系王女士，目标是确认她真正卡在总价还是付款方式。

系统同时生成可复制的跟进内容。

## 人机边界
当前 V1 不调用微信私人账号自动发送，因为没有稳定、合规的官方发送接口。
Skill 自动完成：判断、排序、生成内容、任务编排、状态追踪、结果统计。
人只完成必须由真人完成的最后一步：拨打电话或将内容发给客户，然后点击结果。

未来接入官方 CRM / 企业微信接口后，发送动作可继续自动化。

## 成功标准
不能以“生成了一份方案”为成功。
只有以下结果属于完成：
- 成交
- 明确暂缓并有下次日期
- 明确流失并记录原因

所有未得到结果的客户必须继续留在任务队列中。
